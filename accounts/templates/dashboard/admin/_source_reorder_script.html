{% comment %} Shared drag-and-drop wiring for the page content editor. Two kinds of list are draggable, and both work the same way: drag a row into its new place, the order is POSTed as JSON, and a status line reports the result. [data-sortable="sections"] the page's sections -> page_sections_reorder [data-sortable="source"] the items inside a source -> content_source_reorder The section rows are grabbed anywhere — headings, padding, the lot — so rearranging the page is just dragging the rows themselves. Buttons, links, forms, and the nested editors opt out of starting a drag (`.pc-row__editor` covers the editors, which host their own drag lists and stay editable while a row is in flight). The items inside a source keep their grip handles: those rows are mostly forms, and a handle leaves text selection and typing intact. A third interaction drops a *new* block: dragging a palette tile into the section list posts the source key and the position it landed at. The palette is a narrow sticky rail beside that list rather than a strip above it, so the tile only has to travel sideways into its row — see `.nx-split--rail-right` in page_content_edit.html. Everything degrades safely. If Sortable fails to load, the palette tiles are still buttons that append a block, and each section keeps its ↑/↓ controls. {% endcomment %}
